# Priority and tracking

Outcome: a few priority deliverables, each with an owner and evidence of done. Use the roadmap and paths defined in AGENTS.md.

## 1. Plan a cycle
1. Read the roadmap, goals, work in progress and deliverables already completed.
2. Gather blockers and dependencies before proposing new work.
3. Choose three to five deliverables by impact and effort; do not fill capacity with tasks that have no clear outcome.
4. Write for each deliverable:
   - goal and relation to the objective;
   - owner and contributors;
   - input file/context;
   - artifact or output result;
   - verifiable done criterion;
   - deadline or order, when present;
   - dependencies and risks.
5. Delegate only after each item is complete.

## 2. Track
- Check the delivered file, build, preview or link; a report without an artifact is not completion.
- Classify as done, in progress or blocked, with evidence and next step.
- When a part is missing, follow up once and name the exact gap.
- If the blocker persists, escalate to the user with the decision needed.

## 3. Produce status
Answer in this order:
1. delivered, with evidence;
2. in progress and next milestones;
3. blockers and who owns unblocking;
4. decisions that need the user.

Do not estimate missing metrics. Name the required source, such as analytics, Search Console or revenue.

## 4. Direction changes
A goal change, relevant scope change, new project, publication or deploy follows the approvals in AGENTS.md. Do not turn an idea into execution before that decision.

## Check
Every deliverable has an owner, output and done criterion; every done status has evidence; every pending decision appears explicitly.
